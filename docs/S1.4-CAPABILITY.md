## What the live run proved beyond the unit tests
1. **End-to-end shape**: the ssh-CLI exec seam (same `exec(command)→Promise<string>`
   contract as `createSshTransport`) drives the real poll unchanged.
2. **Live-only bug found & fixed**: the OS section's `tr '\n' ' '` swallows the
   newline before the NEXT `===UPTIME===` marker, gluing it onto the os-release
   line — a whole-line-only parser lost uptime on the real host (showed
   `uptimeSeconds: null` while the unit fixture was clean). Fix: markers are
   recognized anywhere in a line (`splitSections` pre-split). Witness test:
   "markers glued onto a data line are honored" (red on the old parser, green now).
3. **Missing families degrade, never throw**: temperature/draw absent on this
   host → 0, snapshot still `online:true` with every other family.

## Limitations (agentless-Linux truth)
- CPU temperature: 0 when the kernel exposes no readable CPU-ish thermal zone
  (common on VMs/KVM hosts); no fallback daemon install (agentless red line).
- CPU power draw: intel-RAPL only → 0 on AMD; `tdp` always 0.
- Net speed/rate and RAPL draw need a second poll (first poll = 0 by design).
- `net[].ip` and `linkSpeedMbps` are null (would need `ip`/`ethtool` commands
  outside this spec's read-only /proc set).
- Poll interval default 15 s; sample window inside one poll is 0.5 s.

## Deviations found against the spec during live verify
- Spec skeleton claimed `.tmp/live/sshd_config` "already exists" — it did
  (attempt 1 left it + a live sshd on :2222); recipe ran verbatim.
- Everything else in the recipe matched reality; the only live-vs-spec delta
  is the glued-marker parser fix above (spec's command string kept verbatim —
  the fix is parser-side, so LINUX_SAMPLE_CMD stays byte-identical).
