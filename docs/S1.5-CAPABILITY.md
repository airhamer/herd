# S1.5 — macOS (macmon) SSH collector: capability report

**unverified-live — no macOS hardware in the fleet (register S1.5 ruling).**

Nothing in this report was executed against a real Mac. Every statement
below is derived from the fixture-based unit tests
(`server/fleet/__tests__/macosSshCollector.test.js`, 10/10 green) and the
S1.5 spec's macmon design contract (EVAL §1.3). The collector mirrors the
live-proven S1.4 Linux SSH lane structurally; only the macOS-specific
sampling and mapping are new and unproven.

- Collector: `server/fleet/macosSshCollector.js` (`MACOS_SAMPLE_CMD`,
  `parseMacosSample`, `snapshotFromMacos`, `createMacosSshCollector`,
  `createMacosSshFleet`)
- Transport seam consumed: `sshTransport.js` `exec` only (S1.3). One SSH
  call per poll cycle: binary discovery + macmon + native metrics in one
  dash script with `===SECTION===` markers.
- Fleet scoping: registry records with `protocol:"ssh"` AND
  `platform:"macos"` only; the linuxSshCollector lane keeps platform-less
  legacy and `platform:"linux"` records.

## Family capability table

| Family | Emitted? | Source | Notes |
|---|---|---|---|
| `uptimeSeconds` | yes (native) | `sysctl -n kern.boottime` → `{ sec = N, usec = 0 }`, uptime = now − boottime | |
| `cpu.usage` | macmon only | `macmon pipe` NDJSON, total CPU used % (clamped 0–100) | **null when macmon absent/unparseable** |
| `cpu.draw` | macmon only | macmon CPU power (mW) ÷ 1000 → W | 0 when the power field is absent from the NDJSON |
| `cpu.temperature` | **no — 0** | — | macmon exposes no CPU temperature; 0 by tool absence |
| `cpu.tdp` | **no — 0** | — | no portable source (same as S1.4) |
| `gpu` | macmon only | `macmon pipe` GPU used % + GPU power mW → W | **set only when GPU usage % exists**; else `null` |
| `gpu.temperature` | **no — 0** | — | macmon pipe fixture per spec exposes no GPU temp |
| `gpu.powerLimit` / `vram*` | **no — 0** | — | Apple unified memory: there is no discrete VRAM to report; `powerLimit` has no source. `GpuMetrics` (shared/types.ts) has **no name field**, so the spec's `name: "Apple GPU"` is not emitted (types are frozen) |
| `mem` | yes (native) | `sysctl -n hw.memsize` → totalMB; `vm_stat` free+inactive pages × page size → availableMB; used = total − available | page size read from vm_stat, Apple-Silicon default 16384 if absent |
| `disk[]` | yes (native) | `df -P`, 512-block rows → MB | only rows whose filesystem column starts `/dev/` |
| `net[]` | yes (native) | `netstat -ib`, last two numeric columns = Ibytes/Obytes | one entry per interface (duplicate link/inet rows skipped); skips `lo0`, `anpd*`, `awdl*`, `llw*`, `utun*`; rates from poll-to-poll deltas, first poll 0; `ip`/`linkSpeedMbps` null |
| `gpu.processes` | no — `[]` | — | macmon is a SoC reporter, not a process lister |
| `containers` / `versions` / `services` / `memory` / `requests` / `topology` / `tailscale` | no | — | `[]`/`null` per shared/types.ts (agentless lane) |
| `agentVersion` | `"agentless-ssh-1"` | constant | same identity as the Linux SSH lane |

## macmon contract (unverified-live)

- **Binary discovery per poll**, first hit wins: `/opt/homebrew/bin/macmon`
  → `/usr/local/bin/macmon` → `$HOME/.cargo/bin/macmon` → `command -v macmon`.
- **Absent macmon** → MACMON section empty → cpu/gpu null, native families
  (uptime/mem/disk/net) still collected; the absence is logged once per
  node, and the per-poll discovery loop re-probes naturally (macmon itself
  is only exec'd when found). Detection restores cpu/gpu without restart.
- **Root requirement:** upstream macmon needs root/sudo to read IOReport
  private APIs. The wiring assumption is a root-or-passwordless-sudoers SSH
  user on the target — **untested against any real Mac**. A non-root user
  is expected to degrade to the native-only snapshot (macmon section empty),
  not to error the SSH lane.
- **No `timeout` binary on macOS:** the `macmon pipe` stream is closed with
  `| head -n 1` (SIGPIPE ends macmon after one sample). Verified present in
  `MACOS_SAMPLE_CMD` by unit test; not verified that SIGPIPE handling is
  clean on a real macmon build.
- **MIT (vladkens/macmon)**, runs on the target, never vendored.

## schema: pending-upstream-check

The authoritative macmon `pipe` NDJSON field names could **not** be fetched:
`https://raw.githubusercontent.com/vladkens/macmon/main/README.md` → HTTP 404,
fallback `.../master/README.md` → HTTP 404 (both 2026-10-26, one attempt
each per spec). `parseMacosSample` therefore probes several plausible name
variants (`cpu.usage|cpu_usage|cpu.load`, `cpu.power_mw|cpu.power|power.cpu`,
same for gpu, plus flat `gpu_usage`) and degrades to null on any unknown
shape — it will never crash or fabricate a number on schema surprise. The
fixture in the unit tests follows the spec's described content (total cpu
%, per-cluster usage, per-block power in mW, unified memory counters).
**First live run against a real Mac must reconcile the fixture field names
against actual `macmon pipe` output and tighten the mapping.**

## Known limitations

1. Registry-mutation rebuild is out of scope (same documented limitation as
   S1.4): both SSH fleets are constructed at boot from `loadNodes()`;
   adding/changing a macOS record needs a server restart before it is polled.
2. No live proof of any kind (register ruling). Rate math, SIGPIPE close,
   vm_stat page-size handling, netstat column order (`Ibytes`/`Obytes` last
   two columns) and df column layout are fixture-asserted only.
3. `netstat -ib` continuation rows without an interface-name column are
   skipped by the `^[a-z]` name filter; interface-level byte counters are
   assumed identical across a name's rows (first row wins).
4. `enrollment` remains registry-side (never set by collectors); the
   dashboard's `buildFleetSnapshot` overlay supplies it.
